
## Как запустить
1. Перейти во вкладку **Actions**.
2. Выбрать workflow **Secret Scan**.
3. Нажать **Run workflow**.
4. Дождаться окончания (около 5–10 минут).
5. Результаты появятся в папках `applications/<проект>/gitleaks/` и `applications/<проект>/trufflehog/`.

## Методика оценки
*   **Эталонный пункт** — тип секрета из `golden_expected.json`.
*   **Найден** — в логе есть хотя бы одно срабатывание подходящего типа.
*   **Не найден** — у инструмента есть правило, но срабатываний нет.
*   **Не ищет** — у инструмента нет профильного правила (по умолчанию).
*   **Покрытие** = найдено / всего эталонных пунктов.

## Результаты

### Общий итог (27 проектов)
| Показатель | Gitleaks | TruffleHog |
| :--- | :--- | :--- |

| **Найдено** | 52 (57,1%) | 35 (38,5%) |
| **Покрытие без ложных** | 51 (56,0%) | 29 (31,9%) |
| **Только этот инструмент** | 39 (42,9%) | 22 (24,2%) |

### Сильные и слабые стороны

**Gitleaks (охват 57,1%)**
*   **Сильные стороны:** пароли, JWT, приватные ключи, токены Stripe и Slack.
*   **Слабые стороны:** не находит Snyk, Box, SonarCloud, строки подключения к БД. Правило `generic-api-key` дает шум (4282 сработки, из них 3978 в логах `railsgoat`).

**TruffleHog (охват 38,5%)**
*   **Сильные стороны:** строки подключения к БД, Snyk, Box, SonarCloud, DockerHub, ключи сервисов (Gemini, YouTube, Flickr).
*   **Слабые стороны:** не ищет простые пароли, ключи шифрования. Много ложных срабатываний (229 из 544, 42,1%): бинарник `homer-app`, SVG-файлы `haxcms-nodejs`.

## Выводы
1. **Gitleaks эффективнее по общему охвату** (57,1% против 38,5%), но дает много шума.
2. **TruffleHog находит специфичные сервисные ключи** (Snyk, Box, Gemini), которые Gitleaks пропускает.
3. **Использовать оба инструмента.** Если взять только Gitleaks — потеряем 24,2% эталонных секретов. Если только TruffleHog — потеряем 42,9%.
4. **Настроить исключения** для продакшена: `node_modules`, `vendor`, `site-packages`, `log/`, `*.min.js`, бинарники и архивы.

## Ограничения
*   Эталон `default` составлен по результатам самих сканеров (поле `found_in_scanner`), поэтому реальный охват может быть ниже.
*   Для 10 проектов эталон имеет `verified=false` (источники не открывались).
*   Секреты в логах скрыты (`REDACTED`), ложные срабатывания определены по типу файла, а не по значению.
*   Для `DjanGoat`, `xvwa`, `Hospital-Management-System` результатов нет (не удалось клонировать).
